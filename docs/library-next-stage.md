# 日常片库阶段（2026-10-16）

本轮按观看记录 → 首页续看 → 来源增量检查 → 影视归整顺序实施。保留 Flutter/ForUI 与原有分层，不修改 Worker、不部署；不继续排查真实播放。现有 Telegram 账号目录、凭据和媒体数据库未被测试工具打开或清理。

## 使用与行为

1. 播放会保存最后观看时间、实际时长、位置与已看完状态。记录页按时间显示当前账号记录，支持移除单条、确认清空；只移除本机记录与对应续播位置，不删除片库、来源或 Telegram 内容。切换账号后清空确认失效。
2. 片库首页显示最近五条有进度、未完成的记录，直接使用现有播放入口，退出播放器刷新。来源未选中或原文件版本被替换时显示原因并禁用播放；旧记录时间未知时如实标注。
3. 在「导入来源」逐来源「检查更新」。新消息与历史扫描使用独立游标，但共用来源修订号防止旧响应写回；中断后「继续检查更新」，每批原子保存。暂停或进入后台会停止，回到前台不自动继续。
4. 片库可筛选电影、电视剧、待整理。明确年份、`SxxExx` 或 `第2季第3集` 标记的文件名生成本机识别信息；详情支持手动片名、类型、年份、季集及恢复识别。自动识别可能有误，因此明确显示来源；人工修正不被重复导入覆盖。原文件名、说明、来源、文件版本和观看进度保持独立。

新消息检查不回扫旧消息编辑或删除；扫描期间到达的新消息留待下次检查。归整不跨消息合并，不接入在线影视数据库、海报或自动后台同步。

## 数据与实现

- SQLite 事务升级至 v6：v4 观看时间/完成/时长，v5 新消息检查点，v6 文件版本归整。旧位置保留，旧日期不编造；首次归整按 200 条读取，迁移整体失败回滚。错误密钥、高版本或损坏库不重建。
- Domain 新增 `WatchRecord`、`MediaOrganization`；现有 `MediaLibraryRepository` 承接历史、更新与修正，`LocalMediaRepository` 提供账号作用域存储。UI 只使用 ViewModel 和 Domain。
- `LibraryPlayback` 只增加观看状态写入：未真正推进的默认打开不覆盖旧记录，完成与暂停通知分开处理，未改变的进度不重复更新时间。本轮未改下载、缓冲、流控或 Worker 配置。
- 搜索、来源控制、分类、续看和片库列表处于同一滚动区域；860dp 及普通字号使用左右详情，其余进入独立详情。保留 48dp 操作、安全区域和字体缩放。
