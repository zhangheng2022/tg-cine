更新：2026-10-15。用户授权按顺序执行基线收口、真实 Android 片库、iOS 原生交付和远程 CI。本阶段只处理元数据与原生交付，不恢复播放排查。

## 基线

- 静态分析无问题，117 个 Dart 文件格式检查无改动；Flutter 234 项、Worker 64 项及类型/格式/dry-run 通过。Python 4 项中 3 项通过，源码脚本执行项在 Windows 跳过。
- 新 Windows Debug 正常入口已用新目标协议构建并运行。默认服务和中转就绪、手机号页面无错误；当前桌面账号未授权，不计为登录恢复通过。
- Windows 加密片库用只读连接核实仍有 25 条实际媒体版本和 1 个已选来源；没有重新导入、下载视频或删除会话。
- Android 已连接，保留现有正常应用与真实登录。来源保存、导入、搜索/详情、暂停/继续、重开检查待用户选择来源后逐项验收。
- iOS 共享 Dart 逻辑已有回归；XCFramework、带库构建和模拟器运行必须通过 macOS CI，真实账号及真机仍须独立验收。

## 关卡

1. Android：用户在应用选择有权访问的来源并保存；检查元数据批次提交、暂停、恢复及后台停止。只记录计数、布尔值及错误分类，不记录账号、来源、文件名或消息内容。
2. 重开：关闭正常应用再启动，确认无需重复授权，所选来源及媒体记录保留，检查点可继续推进；用实际媒体身份去重，不用文件名去重。
3. iOS：从固定 TDLib 提交构建、验证并嵌入 XCFramework；运行原生 ABI、隔离安全存储及片库集成流程。模板构建、平台变体截图和替身协议均不替代真实账号验收。
4. 收尾：运行相关检查，按源码和 diff 审查，记录 CI 的实际结果和未验收项。当前审查工具只支持 PR CI 查询，无法代替本地差异审查。

当前服务契约与旧客户端更新要求见 [动态目标策略](telegram-network-policy.md)。部署并非本阶段必需步骤，不更改线上 Worker。
