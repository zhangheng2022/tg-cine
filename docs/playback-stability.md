# 播放稳定性验证

更新：2026-10-14。按用户确认的顺序执行；下列状态区分工具实现、实际测量和完整播放验收。

## 执行顺序

| 阶段 | 工作与关卡 | 状态 |
| --- | --- | --- |
| 1 链路计时 | 对齐缓存、TDLib 可读前缀、下载窗、HTTP 队列/刷新、桥接与边缘统计 | 本机有界计时已实现；Worker 脱敏统计已部署。线上 tail 连接超时，尚无同轮边缘统计，不能归因具体网络段 |
| 2 本机校准 | 合成无声/有声视频；文件与 HTTP；只解码、普通 Flutter 与集成测试；输出对照 | 有声 60 秒对照定位到硬件解码路径；当前 Windows 开发入口应用软件解码，最终配置集成测试通过。无声长窗口、1080p 和其他平台仍待验收 |
| 3 缓存与调度 | 一个接收泵按 `@extra` 分发 RPC；缓存读取避免排在冷下载后；同文件仍一个下载窗 | 调度通过真实初始化/授权重开及回归；中点严格 60 秒 GUI 检查通过，片尾失败；回退未新增验证 |
| 4 文件布局 | 同一授权样本比较单/双输入、索引位置及重新交错后的需求 | 受限读取后生成片尾片段；本地文件与 HTTP 60 秒检查通过。尚无同样缓存条件的原布局对照，不能单独归因布局 |
| 5 恢复与长播放 | 配额、到期、断连、媒体版本校验后恢复；长时间播放 | 实际播放器配额失败与新来源重试通过；到期解析和传输关闭边界回归通过。真实断网、版本化续看和完整电影未验证；限额保持原值 |

## 持续播放判定

每个定位点独立观察约 61 秒，准备和冷定位等待另记。UI 位置、原生 `time-pos`、实际选中音轨的 `audio-pts` 均须在墙钟时间的 98%–102% 内前进；进度无变化间隔不超过 1 秒、没有缓冲、绝对音视频差不超过 500 ms。缺失原生时钟不能计为通过。无声视频不要求音频时钟。

`time-pos` 不是独立视频 PTS；内存截图变化也不证明屏幕实际呈现。合成移动画面另要求至少 55 次快照变化。旧 8 秒用例的“通过”仅是历史门槛，不能算作新的稳定播放验收。

## 本机校准记录

同一 65 秒、320×180、10 fps 合成视频；有声版带静音播放的 44100 Hz 音轨。使用当前安装的 mpv `v0.36.0-403-g652a1dd907`。真实影片的画面和身份不进入报告。

| 路径与输出 | 观察时间 | 最长进度间隔 | 缓冲 | 快照变化 | 结果 |
| --- | --- | --- | --- | --- | --- |
| 本地文件 / 只解码 | 60.900 秒 | 256 ms | 0 | 60 | 通过 |
| 本地 HTTP / 只解码 | 60.853 秒 | 258 ms | 0 | 59 | 通过 |
| 本地文件 / 集成测试硬件纹理 | 60.983 秒 | 23.092 秒 | 0 | 38 | 失败，音频连续前进 |
| 本地文件 / 普通 Flutter 硬件纹理 | 60.839 秒 | 22.947 秒 | 0 | 38 | 失败，音频连续前进 |
| 本地文件 / 普通 Flutter 软件解码和输出 | 60.819 秒 | 231 ms | 0 | 59 | 通过 |
| 本地文件 / 普通 Flutter 软件解码、硬件输出 | 60.829 秒 | 228 ms | 0 | 60 | 通过 |
| 本地文件 / 修复配置集成测试 | 60.821 秒 | 212 ms | 0 | 60 | 通过，原生属性确认 `hwdec=no` |

集成测试失败轮的 230 次 Windows 前台检查全部为真；因此该轮不能再简单归因于失焦。Flutter 生命周期采样仍为 `inactive`，需与 OS 前台状态区分。普通 Flutter 对照使用生产 App、页面、导航和播放后端，避免把测试绑定作为唯一变量。保留硬件输出而关闭硬件解码的对照通过，将范围缩小到本机硬件解码路径；具体驱动、码流或解码器原因仍未确定，不证明原大样本已经稳定。

Windows Debug 私有媒体入口的 `VideoController` 已设置 `hwdec=no`，继续使用原来的 GPU 渲染；其他平台未强制改用软件解码。软件解码可能增加 CPU 使用和耗电，320×180 合成样本通过不证明 1080p 原样本或所有 Windows 设备通过。

MP4 索引核对显示视频单样本时长最大 100 ms、组合时间偏移最大 300 ms，没有与 23 秒停顿对应的大时间戳跳跃；这只验证索引，不能证明码流无损。早期采样因无效原生属性中断，以及暂停后跳转产生的空属性结果，不计入播放结论。

## 工具与证据

### 原大样本中点对照

两轮均为 1,259,802,293 字节、1920×960 原样本；软件解码、双输入、2 MiB 下载窗、4 MiB 读取缓存和新服务的 128 MiB / 512 请求预算相同。1490 秒定位后再前进 2 秒才开始观察。

| 调度 | 恢复条件等待 | 墙钟 / 视频进度 | 最长进度间隔 | 累计缓冲 | HTTP 字节 | 判定 |
| --- | --- | --- | --- | --- | --- | --- |
| 原全读取串行 | 7.616 秒 | 60.869 / 56.533 秒 | 3.049 秒 | 4.755 秒 | 57,942,068 | 失败 |
| 可读数据旁路、RPC 分发 | 8.535 秒 | 60.832 / 60.833 秒 | 408 ms | 0 | 61,005,876 | 通过 |

源读取失败和并发拒绝均为 0，均未耗尽预算。冷读取队列累计等待由 61.0 秒降到 32.0 秒；这是重叠请求总计，包含准备过程，不等于墙钟停顿。第二轮读取更多字节，是因为实际连续播放更长；不能只用总字节判定效率。网络条件不同，单轮对照不证明所有环境可靠。

`TdlibDispatcher` 保持单一 5 ms 接收泵，每轮最多 32 事件、64 个未完成请求，按客户端与 `@extra` 对应，超时/关闭移除待处理请求并忽略迟到回复。`MediaProbe.readReady` 只读内存或 TDLib 已确认可读的范围，不启动或取消下载；只有冷范围进入原下载队列。HTTP 保留双活动/双等待、同流替换和预算预留。关闭后及过期响应不会把字节送给播放器。

### 片尾与重新封装对照

原布局 2906 秒检查等待约 8.437 秒恢复；随后 60.926 秒仅前进 32 秒，累计缓冲 19.776 秒，最长进度间隔 4.562 秒，失败。8 次请求共 54,517,812 字节，读取失败、并发拒绝和预算耗尽均未发生。可读前缀累计等待 92.1 秒，冷队列累计等待 65.5 秒，均包含准备和重叠请求。桥接本机写入最大 1.49 ms，未触发字节、时长或确认超时限制；这些数字仍不足以区分 Worker→Telegram 与设备→Worker 的网络供给。

使用 VLC 流复制请求 2906–2971 秒；经受限 HTTP 读取 79,835,162 字节、76 次请求，122 秒生成 35,247,535 字节片段。读取和并发拒绝为 0，预算未耗尽。实际时长约 71.5 秒，包含前置关键帧，不是严格相同的 65 秒窗口。片段仅保存在账号的受限本机目录，不修改原选消息或原文件；不是从稀疏文件的未知空洞复制。

重新封装后，30 秒处视频/音频文件位置差约 24 KiB，60 秒处差约 24 KiB；原布局对应片尾音视频位置相距约 514 MB。该元数据差异表明重排改善了交错，但播放对照同时改变了网络供给和文件布局，不能用它证明布局是唯一原因。

| 重新封装片段 | 墙钟 / 原生位置进度 | 最大进度间隔 | 缓冲 | 结果 |
| --- | --- | --- | --- | --- |
| 本地文件、单输入、软件解码/GPU 输出 | 60.968 / 60.967 秒 | 361 ms | 0 | 通过 |
| 本地 HTTP、单输入、软件解码/GPU 输出 | 60.761 / 60.766 秒 | 472 ms | 0 | 通过 |

HTTP 轮确认 1920×960 和 44100 Hz，完整读取 35,247,535 字节，读取错误和预算耗尽为 0。自然影片只要求画面确有变化；55 次以上的固定门槛仅适用于合成移动画面，所有样本的时钟与缓冲门槛相同。下一步应隔离原文件缓存与网络变量，再决定按音轨映射读取或来源侧重新封装，不能直接批量改写用户片库。

### 受控失败和恢复

`Windows playback fails safely at quota and retries with a fresh source` 在真实 NativePlayer 与 Flutter 页面上通过：先耗尽测试用 1 字节端点的预算，确认播放器失败且操作结束；更新测试来源后重试，确认 1920×960 首帧与至少 2 秒进度，位置从开头重新开始。测试只缩小测试端点配额，不提高正式开发限额。第一次运行因页面转场尚未完成而无法获取 ViewModel，补上页面就绪等待后通过，不将这个测试调度错误当成播放错误。

来源过期、HTTP 限额、关闭清理及 Worker 断连/确认超时的自动回归继续通过；它们不能代替真实网络中断与长时间恢复。当前没有保存版本化续看进度，重试成功不等于自动恢复旧进度。所有本轮服务已撤销清单、关闭 TDLib 和桥接，账号锁释放，原消息选择未变；重新封装片段保留在受限账号目录供后续对照。

- `tool/support/playback_trace.dart`：最多 4096 条数字事件，溢出保留总计；不接受任意错误文本、URL、消息或账号信息。
- `tool/support/playback_observer.dart`：实际时钟及内存画面采样，集成测试与普通入口共用。
- `tool/player_calibration.dart`：普通 Flutter 校准入口，自动走现有片库播放操作；用于本机合成视频与授权片段，不接受外部网络 URL。
- `integration_test/player_test.dart`：支持文件/HTTP、只解码和手动前台门控；远距离检查用 `midpoint`、`midpoint-back`、`tail`、`tail-back` 独立选择，片尾提前 75 秒避免窗口撞到结尾。

在 `app/` 执行普通校准，例如：

```powershell
flutter run -d windows -t tool/player_calibration.dart --dart-define=TG_CINE_CALIBRATION_MEDIA_FILE=<合成视频绝对路径> --dart-define=TG_CINE_TEST_OUTPUT_DIR=<已忽略的绝对输出目录>
```

`TG_CINE_SOFTWARE_OUTPUT=true` 仅用于同时关闭硬件输出和硬件解码的对照；`TG_CINE_SOFTWARE_DECODE=true` 用于保留硬件输出的解码对照。`TG_CINE_CALIBRATION_HTTP=true` 以受限回环服务代替文件输入；授权自然影片使用 `TG_CINE_MOVING_FIXTURE=false`，不得用这个参数放宽合成移动画面检查。参数只控制校准入口；Windows Debug App 的修复配置在组合根中明确设置。数字输出位于已忽略的 `.cache/flutter-player-review/`，授权片段位于账号受限目录；画面截图只在内存比较。

Worker 当前版本为 `0e133901-bbc3-4067-bc4d-94aea5b8f7ff`；上线版本与源码摘要已核对。连接标识随机生成，不包含 Telegram 身份。64 MiB / 15 分钟 / 30 秒空闲和固定目标白名单保持原值。本机工具仍受 128 MiB / 512 请求 / 20 分钟约束，不能验证完整电影。

本轮 Flutter 静态分析和 109 项单元/组件测试通过，新增覆盖乱序回复、客户端过滤、更新顺序、迟到回复、请求上限、退出清理、可读旁路、短读取、旁路关闭与关闭中不得启动新下载。固定 TDLib 1.8.68 的真实 ABI、初始状态与关闭也通过。Worker 49 项测试与类型、实际配置 dry-run 通过。Code Review 仅有 PR CI 查询接口，本地审查依据源码和差异；远程 CI、实际听感、手机真机及其余平台未实测。
