# 作品片库与整理（2026-10-16）

本轮顺序为真实元数据验收、作品归组、季集与版本选择、批量整理。保留 Flutter/ForUI、现有分层及账号数据；未改播放下载、缓冲调度或 Worker，未部署、提交或推送。

## 入口与行为

- 「片库 → 作品片库」按作品浏览；作品详情按季集排序，同一集多个当前文件分别保留原文件名、来源和大小，通过文件详情复用现有播放入口。只列实际已有集数，不推测总集数或制造缺失集。
- 自动归组只使用确定的类型、去除首尾空白并忽略大小写的片名、年份；不同年份分开，未知年份不会并入已知年份。未识别文件保留在原文件列表及待整理筛选。没有联网资料或模糊标题匹配，同名同年仍可能需要人工拆分。
- 「整理文件」支持搜索、待整理筛选、分页选择；每批最多 100 个文件。可选择已有作品，或新建独立作品以拆分同名条目。共同片名、年份、类型统一确认；电视剧季集逐条填写并验证，预览具体文件及目标季集后整批保存。
- 「撤销选中归组」须确认，只解除归属；原文件、人工信息和观看记录保留，文件仍在「整理文件」中。撤销标记持久化，重复导入不会重新归组；之后可再次手动归入作品。它不是删除媒体或清空影视信息。
- 人工归组不被导入覆盖。单文件修正如果改变共同片名、年份或类型，会退出原有人工组，避免文件信息与作品相互矛盾；只修正季集则保留归属。保存失败保留表单，账号或来源选择改变后旧页面和提交均失效，含顶部作品标题。

## 数据与架构

SQLite v7 在同一事务增加 `works` 与 `work_members`，按 200 条读取既有影视归整信息建立关系。作品、成员关系和文件版本独立保存，文件版本键、来源、历史/更新游标与观看记录不重写。作品只汇总已选来源的当前文件版本，替换的旧版本不会伪装成可用文件。

查询和编辑沿用 `LibraryViewModel → MediaLibraryRepository → TdlibTelegramRepository → LocalMediaRepository`。所有读写绑定账号；作品与成员有账号范围外键。批量修改先校验当前来源/版本以及每条季集，任一条失效则整个事务回滚。查询按 50 条分页，不能把已加载的一页误当整部作品；没有新增网络服务或依赖。

## Android 模拟器补验

用户选择使用现有 Pixel 10 模拟器（Android 16 / API 36 / x86_64，`emulator-5554`）。初始未安装 TG Cine；测试使用临时加密数据库和设计数据，不复制桌面 Telegram 会话。模拟器结果单独记录，不替代移动真机验收。

`integration_test/mobile_library_stage_test.dart` 复用作品事务测试，在 Android 平台 SQLite 上验证迁移、归组、重开、失败回滚与账号隔离；`library_test.dart` 的协议测试验证系统安全存储、加密片库、导入与重开。真实元数据测试 `real_library_update_test.dart` 已支持 Android/iOS 原生入口，须先在正常应用中交互登录并保存来源，只输出汇总数量。
