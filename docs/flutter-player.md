### 请求抖动修复

- 原生端在打开媒体前设置 `stream-buffer-size=32 MiB`。依据 [mpv 官方说明](https://mpv.io/manual/stable/#options-stream-buffer-size)，低层缓冲支持回读，可缓解 MP4 的短距离定位；它与包缓存不同。本轮关闭 `media_kit` 默认启用的磁盘缓存：磁盘模式下字节上限仅限制包元数据。现在包缓存设为 8 MiB，预读时间上限为 10 秒，依据 [缓存说明](https://mpv.io/manual/stable/#options-cache-on-disk)。有音轨时使用独立音频输入，每个输入都有自己的缓冲；不能将 32 MiB 当作播放器总内存。Web 条件导入仍使用空实现。
- Flutter 私有服务为视频路径及其 `/audio` 别名提供同一文件。先加载轨道，再仅对有音轨的媒体添加音频输入；无声音轨的视频保持单输入。每条流的新有效 GET 只替换本流的旧响应，只有旧响应正在执行原生读取时才取消该读取。HEAD、无效 Range、错误路径及另一条流不会误取消。普通解码检查默认仍允许同路径重叠。
- 同时最多两个活动响应、两个等待请求，超过后返回 503；读取仍串行，先预留预算。截断响应使用关闭期限销毁连接，不尝试在已发出头部后分离套接字。128 MiB / 512 次上限不变；收尾报告增加排队、拒绝计数及范围的数字流类别，不包含私有 URL。

60 秒首次定位等待 28.8 秒；回到 10 秒与 45 秒约 2.2 秒。这里测量的是“定位后进度继续前进至少 2 秒”的验收时间，不能直接当作定位首帧延迟；冷定位还有下载等待。最新脱敏报告为输出目录的 `playback-result.json`，服务收尾记录范围偏移、返回字节及预算状态，位于私有账号目录的 `flutter-media-result.json`，不含私有 URL 或消息身份。

每次完整真实检查应重新启动有界服务，不能累计多轮后忽略读取预算。本轮已移除自己创建的清单并正常关闭服务，确认账号锁释放，原大样本选择保持不变。

当前环境的 Code Review 能力只支持 PR CI 查询，未提供本地 diff 审查接口；本次审查依据源码、相关调用与差异，覆盖 UI/Data 分层、开发配置隔离、来源校验、命令并发和生命周期。CI 扩展 integration_test 格式检查与 Linux mpv/epoxy 构建依赖，未运行远程 CI。

## Android 模拟器黑屏修复（2026-10-16）

Pixel 10 / Android API 36.1 模拟器播放真实 Telegram 视频时，音频时钟前进但画面全黑。原生日志显示 `EGL_BAD_ATTRIBUTE`、`Could not create a GL context`，随后 `vid=no`、`vo-configured=no`。视频是 1920 × 808 的 HEVC；这轮问题定位到视频输出初始化，不以此解释此前的下载缓冲。

当前 Android 库包含 mpv `v0.36.0-549-g78d43740f5`，其 EGL 创建流程始终传入 context flags；[对应源码](https://github.com/mpv-player/mpv/blob/78d43740f5/video/out/opengl/egl_helpers.c)与[上游 API 36 黑屏记录](https://github.com/media-kit/media-kit/issues/1343)提供了排查依据。本机将 `gpu-debug` 设为 `yes` 后恢复画面，单独切换模拟器软件 GPU 未解决。客户端复用已锁定的 `media_kit_video` 插件 `Utils.IsEmulator` 检测，仅在 Android 模拟器打开该选项，待捆绑的 libmpv 修复后移除。真实设备和其他平台不应用此临时处理；调试图形上下文可能增加模拟器渲染开销。
