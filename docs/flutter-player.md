## 本机启动

当前真实媒体接入限 Windows Debug。登录、频道选择和 TDLib 生命周期由现有本机工具持有；不是完整的应用内 Telegram 接入。API 凭据、TDLib 会话与 Worker 令牌不写入 Flutter 配置或发行客户端。播放器依赖依据 [media_kit 官方说明](https://pub.dev/packages/media_kit) 接入。

在 `app/` 的本机终端中运行以下命令，API 文件使用已存在的本机路径：

```powershell
$env:TG_CINE_RELAY_TOKEN_FILE = (Resolve-Path ../.cache/deployment/relay-token.txt).Path
dart run tool/telegram_login.dart ../.cache/native/build-windows/Release/tdjson.dll ../.cache/deployment/relay-bridge.json '<本机 API .env 路径>' --serve-media
```

等待“Flutter 私有媒体源已就绪”，保持终端运行，在另一终端进入 `app/`：

```powershell
$mediaFile = (Resolve-Path ../.cache/native/accounts/dev-account/flutter-media.json).Path
flutter run -d windows --dart-define="TG_CINE_DEV_MEDIA_FILE=$mediaFile"
```

在片库点击“播放所选视频”。该入口不会更改原有频道/消息选择。普通启动继续显示空片库；Web、其他平台及 Release 不启用此开发配置。

媒体清单位于已保护的账号目录，只含随机回环地址和有效期，不输出到日志；客户端限制大小、协议、IPv4 回环地址、显式端口、随机路径及有效期，拒绝外部地址和附加查询。服务最长 20 分钟，最多读取 128 MiB / 512 次范围请求；这是有界开发验证，不能观看完整的大样本。Ctrl+C、删除自己创建的 `flutter-media.json` 或到期会关闭新版本服务，并释放媒体读取、TDLib、桥接和账号锁；关闭 Flutter 仅释放播放器。

### 请求抖动修复

- 原生端在打开媒体前设置 `stream-buffer-size=32 MiB`。依据 [mpv 官方说明](https://mpv.io/manual/stable/#options-stream-buffer-size)，低层缓冲支持回读，可缓解 MP4 的短距离定位；它与包缓存不同。本轮关闭 `media_kit` 默认启用的磁盘缓存：磁盘模式下字节上限仅限制包元数据。现在包缓存设为 8 MiB，预读时间上限为 10 秒，依据 [缓存说明](https://mpv.io/manual/stable/#options-cache-on-disk)。有音轨时使用独立音频输入，每个输入都有自己的缓冲；不能将 32 MiB 当作播放器总内存。Web 条件导入仍使用空实现。
- Flutter 私有服务为视频路径及其 `/audio` 别名提供同一文件。先加载轨道，再仅对有音轨的媒体添加音频输入；无声音轨的视频保持单输入。每条流的新有效 GET 只替换本流的旧响应，只有旧响应正在执行原生读取时才取消该读取。HEAD、无效 Range、错误路径及另一条流不会误取消。普通解码检查默认仍允许同路径重叠。
- 同时最多两个活动响应、两个等待请求，超过后返回 503；读取仍串行，先预留预算。截断响应使用关闭期限销毁连接，不尝试在已发出头部后分离套接字。128 MiB / 512 次上限不变；收尾报告增加排队、拒绝计数及范围的数字流类别，不包含私有 URL。

60 秒首次定位等待 28.8 秒；回到 10 秒与 45 秒约 2.2 秒。这里测量的是“定位后进度继续前进至少 2 秒”的验收时间，不能直接当作定位首帧延迟；冷定位还有下载等待。最新脱敏报告为输出目录的 `playback-result.json`，服务收尾记录范围偏移、返回字节及预算状态，位于私有账号目录的 `flutter-media-result.json`，不含私有 URL 或消息身份。

每次完整真实检查应重新启动有界服务，不能累计多轮后忽略读取预算。本轮已移除自己创建的清单并正常关闭服务，确认账号锁释放，原大样本选择保持不变。

当前环境的 Code Review 能力只支持 PR CI 查询，未提供本地 diff 审查接口；本次审查依据源码、相关调用与差异，覆盖 UI/Data 分层、开发配置隔离、来源校验、命令并发和生命周期。CI 扩展 integration_test 格式检查与 Linux mpv/epoxy 构建依赖，未运行远程 CI。

## 本轮远距离验收：尚未通过

中点音视频文件位置相距约 254 MB。只增加独立音频输入仍失败，旧响应占用两个并发位置，中点请求没有进入读取。区分读取流并取消同流旧响应后，1490 秒定位约 17.3 秒达到“进度继续至少 2 秒”的条件，画面有变化、音频时钟前进、瞬时音视频差为 0；但随后 8.15 秒只播放 3.4 秒，最大进度停顿 4.62 秒，持续播放验收失败。该对照共 11 次请求、33,775,668 字节，源读取失败和并发拒绝均为 0，限额未耗尽；不能据此宣称已经流畅播放。

本机生成的无声 MP4（320×180，5.8 秒）通过 HTTP、直接文件、硬件与软件输出对照，持续播放检查都停在约 1.4 秒；当时速度为 1，播放器未暂停、未缓冲，窗口处于非活动状态。这说明失败不只涉及 Telegram/Worker 下载；具体的窗口或渲染原因尚未证实。用户选择稍后人工验证，因此本轮不再推进依赖前台窗口的验收。

最终的关闭磁盘缓存和 10 秒预读配置，通过无声视频打开、首帧、至少 500 ms 进度、重新打开与轨道回归检查；NativePlayer 查询确认配置生效，没有请求音频别名。这是打开/重开与无声分支证据，不是持续播放证据。最终配置下的原大样本中点、片尾及其回退仍待前台复测。失败报告保留在已忽略目录，不降低远距离用例的持续播放门槛。

### 只解码对照与有界预取

继续排查时，用同一合成无声视频设置 `vo=null`、`vid=auto`，保留实际视频解码和内存截图，绕开 Flutter 纹理输出。约 2.025 秒内播放时钟前进 2 秒，解码快照可用。该结果将本机文件的冻结范围缩小到输出/渲染链路，但没有证明具体窗口或驱动原因，也没有替代前台人工验收。

真实远距离用例增加 `TG_CINE_DECODE_ONLY=true`，仍经过 App、PlayerViewModel、来源校验、实际视频解码、独立音频输入和定位命令。两张画面只在内存中比较，验证音频时钟和音视频差；输出写入 `distant-decoder-result.json`，不覆盖纹理输出报告，也不记录私有画面或 URI。每轮使用新服务和相同预算，网络条件仍可能波动。

最终保留配置的片尾附近（2936 秒）检查仍失败：定位恢复等待 11.8 秒，随后 8.14 秒只前进 3.37 秒、音频前进 3.38 秒，最大进度停顿 2.64 秒；画面有变化、瞬时音视频差为 0。8 次 HTTP 请求共 25,305,140 字节，读取错误、并发拒绝均为 0，预算未耗尽。绕过纹理输出后仍有持续停顿，读取供给与缓存恢复链路需要继续排查，不能等待前台人工验证后就假定它已经解决。

两个未保留的有界试验也未完成片尾用例：等待 5 秒缓存后，2936 秒窗口前进 7.6 秒，但回退至 2926 秒只前进 1.33 秒、最长停顿 6.89 秒；扩大预取至 4 MiB 的 2936 秒窗口只前进 4.1 秒。已撤销缓存等待参数并恢复 2 MiB，不降低原用例要求。下一步需核对两条轨道的有效吞吐和预取调度，不能以增加缓冲替代持续吞吐验证。

读取器启动新的 2 MiB 窗口后，等待窗口末端可读再返回第一块；已缓存和未切窗的读取仍按请求量检查。保留 512 KiB 原生读取、4 MiB 内存缓存、串行 RPC、协作取消和两分钟下载等待。播放器将 `media_kit` 的 5 秒 HTTP 超时改为 30 秒，减少冷范围等待及串行轨道读取被提前重连的机会，仍是有限超时。参数语义见 [mpv 网络超时说明](https://mpv.io/manual/stable/#options-network-timeout)。较慢失败检测是此改动的代价；不增加下载窗口、内存预算或总读取限额。

重复只解码对照时，使用远距离用例名选择测试，并加上 `--dart-define=TG_CINE_DECODE_ONLY=true`，片尾另加 `--dart-define=TG_CINE_SEEK_CHECKPOINT=tail`。本机文件校准用例为 `Windows native decoder advances without Flutter texture output`，通过 `TG_CINE_SILENT_MEDIA_FILE=<无声合成视频绝对路径>` 提供对照；它不依赖 Telegram。音频时钟和静音解码检查不等于实际听感验收。

真实检查须用 `--plain-name` 选择用例，每轮重新启动服务。远距离用例名为 `Windows Flutter keeps audio and video advancing after distant seeks`，默认中点及回退 10 秒；附加 `--dart-define=TG_CINE_SEEK_CHECKPOINT=tail` 检查片尾附近及回退。画面仅在内存中比较，不保存私有媒体截图；等待使用实际时间与持续渲染策略。原生 GUI 校准失败时，不能将测试框架超时当成下载慢的唯一证据。
