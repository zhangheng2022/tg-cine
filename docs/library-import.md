# 历史导入与原始片库

更新：2026-10-15。iOS、Android 共用实现，手机与宽屏同步；本轮只导入授权来源的元数据，不下载视频、不恢复播放排查。

## 使用流程

1. 原生客户端使用内置默认服务完成 Telegram 授权，在「来源」选择并保存；私有 Debug 配置保留给开发验证。
2. 进入「片库 → 导入来源」，逐来源开始或继续。应用前台按批整理，每批保存后即可浏览；可暂停，后台也停止，返回前台需手动继续。
3. 搜索原文件名、原消息说明或来源名称。条目显示来源、大小、已知时长；文档形式视频没有时长时明确显示未知。
4. 手机打开文件详情，宽屏并排预览；字号较大时回到独立详情。详情保留完整文件名和原说明，可主动复制 Telegram 源消息链接。

已经完成历史扫描的来源不自动扫描新消息；暂无影视资料识别、海报、待整理纠正、自动增量同步或片库条目播放按钮。既有开发播放器入口独立于本流程。

## 调用与一致性

`LibraryView → LibraryViewModel → MediaLibraryRepository → TdlibTelegramRepository → TelegramHistoryService / LocalMediaRepository`。UI 不直接使用 TDLib 或 SQLite；组合根创建与释放共享账号和片库依赖。

- `searchChatMessages` 每页最多 50 条，不限制消息过滤器；解析普通视频与 MIME/扩展名可识别的视频文档，跳过非视频和自毁内容，不调用 `downloadFile`。
- 使用服务端 `next_from_message_id`。短页或无视频页仍保存游标，只有游标为 0 才完成；不推进、畸形或缺少稳定文件身份的页失败，不跳过后推进。
- 媒体及检查点同一事务提交。暂停、来源取消选择、账号切换或会话关闭会使旧响应失效；数据库修订号进一步拒绝旧批次。
- 重开会话先恢复本机来源，再让 TDLib 加载主列表/归档中的聊天实体，随后读取历史；保存的 ID 不等于原生聊天缓存已经就绪。
- SQLite v3 增加来源名称；搜索参数绑定，保持账号隔离。元数据、名称和检查点保存在独立加密库，密钥缺失或迁移失败不覆盖原文件。
- 源消息链接仅允许 HTTPS Telegram 域名，并校验当前账号、选中来源和已有实际媒体版本；无法生成链接时显示失败，不编造地址。

## 验证与边界

全量 199 项 Flutter 测试和静态分析通过，覆盖协议解析、事务去重/升级、暂停/旧响应、账号隔离、查询、链接和 UI 交互。组件矩阵覆盖 Android/iOS 平台变体、320/800/1440 宽度、明暗及 1.0/2.0 字体，另补 320×568 双倍字体失败/恢复测试。

Android NE2210 真机与 Windows 的协议替身 → 真实加密 SQLite → Flutter 导入、去重及重开恢复验收通过，使用隔离数据与独立密钥，结束清理。Windows 真实授权来源两次独立进程批次累计保存 25 个媒体条目，检查点推进，历史未结束；输出仅保留计数，不捕获私有片库或消息信息。

普通入口 Android Debug APK、Web 与 Windows Debug 构建通过。48 张 Windows Flutter 设计数据截图及 Impeccable 修复复审通过，不能替代移动渲染验收；一次截图采集等待帧超时，单独重跑后补齐并通过。

iOS 没有本机 Xcode，未编译、签名或真机验证；Android TDLib 已交付且真实登录通过，iOS 原生仍待交付；真实移动 Telegram 导入尚未验收，后续记录见 [阶段验收](library-acceptance.md)。Web 保留未连接状态。远程 CI 未运行，本轮未提交代码或部署 Worker。
